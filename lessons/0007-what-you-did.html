39 and 40. Explain one method, then change it

If he points at a method, use this shape. Example: RefundBand.cents.

  1. It takes the ticket’s net, the time now, and the show time.
  2. It measures the real gap between those two instants.
  3. If the gap is 168 hours or more, it returns the whole net.
  4. If the gap is still at least 48 hours, it returns half the net, rounded up.
  5. Otherwise it returns zero. It does not add the fee. The caller does that only for an event cancel.

A live change means: name the rule that must stay true, change the smallest bit of code, then change the test that locks the old edge. Part 6 practices that out loud.

42, 43, and 44. Two more days, and why this shape

A simpler design would keep a database lock open for 10 minutes, or store only a yes-or-no on the seat. The lock dies if the app dies and blocks other work. A yes-or-no cannot keep a released hold in history. The timestamp plus the partial index does both.

With two more days, the next work from the notes is: admin screens, a sales screen, a seat map that updates while it is open, then a real card charge and tax. A background worker would release expired holds and finish unknown payments without waiting for someone to open the event.

Left incomplete on purpose: no admin site, no setup screens, no live map, no real charge, no tax, no second promo, no scheduler. Say that list without saying sorry.

Say this
