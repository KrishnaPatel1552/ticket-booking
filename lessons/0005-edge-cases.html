The odd cases

Questions 16 to 25. Each one is a story. Answer with what the code does, not what sounds fair.

16. Ten tickets, then a hold for three

The event cap is 12. She has 10, so 2 spots remain. The request asks for 3. Three is more than 2, so we write no holds and return the event-limit error.

Say this

She is over the room she has left, so the whole request fails. I do not hold two and drop one.

17. When cancelled tickets leave the cap

They still count while the refund is pending or unknown, because the tickets are still on the order. They stop counting when that refund succeeds and the tickets come off. Then those seats can be held again.

Say this

They leave the cap when the cancel refund succeeds, not when she first clicks cancel.

18. Block a seat that is already held

The hold wins. The block fails. The seat stays held. If the seat were free, the block would win and a later hold would fail.

Say this

Whoever locks the seat first keeps it. A block does not kick out a hold.

19. Exclusive promo during early-bird

Normal price order: early-bird price, then the group rate, then one promo. An exclusive code skips that. It starts from the normal tier price, uses a group discount of zero, then takes its own amount off.

If the code is already used up, we skip it and charge the normal price. Checkout still completes.

Say this

Exclusive means no early-bird and no group rate. Only that code, on the normal price. A used-up code is skipped, not a failed checkout.

20. One promo use, two checkouts

We lock the promo code. A pending or unknown payment already counts as a use, before the amount is saved. The first checkout to get the lock takes the last use. The second checkout still pays, but without the discount.

Say this

The first checkout locks the code and takes the last use. The second one still checks out at the price without that code.

21 and 22. Fifty hours, and the fee

Fifty hours is in the half band. She gets half that ticket’s net. Half of an odd net rounds up. She does not get the fee.

If an admin cancels the event, the refund is the full net plus that ticket’s fee share. Those seats are not put back on sale.

Say this

Her cancel at 50 hours returns half the net and keeps the fee. An admin event cancel returns the net and the fee, and the seats stay off sale.

23 and 24. Waitlist

Opening the event releases an expired hold that has no payment, then offers the next waitlist person a hold of 15 minutes. The caps still apply. If that person is already at 12, we skip them and offer the next person. The skipped person stays on the list for a later seat.

Say this

A freed seat goes to the next person who still has room, as a 15-minute hold. Someone at the cap is skipped, not removed.

25. What we left out

Say this without apologizing. The point of the build was correct behavior.

  • No admin website. Admin actions are API calls with a reason and an audit row.
  • No screens to create the venue. Starter data supplies Harbor Hall.
  • No live seat map. The page reloads after your own action.
  • No real card charge. The caller picks success, decline, timeout, or unknown.
  • No tax, no second promo, no percent-off code, no background timer.

Say this

Those are cuts, not bugs. I would add admin screens, a live map, a real charge, and a worker that finishes unknown payments.
